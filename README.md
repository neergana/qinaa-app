# قِناع | QINAA — نموذج الويب للهاتف

**الحقيقة خلف القناع.** · `qinaaapp.com`

نموذج واجهة عربية RTL يعمل مباشرة في المتصفح، ومصمم ليكون قاعدة لنسخة PWA ثم تطبيق هاتف لاحقاً.

## ما يعمل الآن

- تنقل كامل بين الصفحة الرئيسية، الردهة، القواعد، والجولة.
- دليل غرف عامة على الرئيسية، مع دخول اللاعب بعد إنشاء حساب محلي تجريبي أو مشاهدة الغرفة العامة بلا حساب.
- إنشاء ودخول غرف حقيقية محفوظة في Cloudflare D1، مع إعداد الخصوصية وإدارة المضيف للأعضاء.
- كشف الدور، قرارات أفراد الظل، اختيار الهدف، ومحادثة نصية حية.
- أسماء الأدوار المعتمدة: أفراد الظل، البريء، المُنقذ، الشيخ — كاشف الأسرار، الخطّابة — رابطة القلوب، والساحرة — حارسة الجرعات.
- الكشّاف يفحص ثلاثة لاعبين ليلاً ويحصل على نتيجة جماعية فقط. «عين الليل» اسم مقترح ودورها قيد الموازنة ولا يدخل التوزيع حالياً.
- نهار بمؤقت 4 دقائق يتوقف أثناء أول مداخلة (دقيقتان) والمداخلات التالية (دقيقة)، مع طابور ينتقل تلقائياً وتحكم ذاتي للمتحدث.
- محادثات الجولة حيّة عبر WebSocket وDurable Objects، وتُحفظ في D1 ثم تُحذف تلقائياً عند إنهاء الجولة.
- حسابات حقيقية وجلسات HttpOnly، تسجيل عادي، وتسجيل عبر Google وFacebook يطلب مرة واحدة فقط المعلومات المطلوبة التي لم توفرها المنصة.
- عشرة أقنعة SVG للملف الشخصي، مع صفحة مستقلة لتعديل الاسم واسم المستخدم والميلاد وكلمة المرور.
- الميكروفون مطفأ افتراضياً، ولا يطلب المتصفح الإذن إلا بعد ضغط اللاعب على زر التشغيل؛ يمكن إيقاف الالتقاط في أي وقت.
- الصوت المباشر يعمل عبر LiveKit برموز دخول قصيرة العمر يصدرها Cloudflare؛ للمشاهد استماع فقط، ولأفراد الظل قناة ليلية منفصلة.
- اختيار ثم تأكيد مستقل لقرارات الليل والتصويت، وانتقال آلي فور اكتمال التأكيدات من دون انتظار المؤقت.
- تصويت حي 60 ثانية وكشف الهويات بعد الإغلاق. النتيجة المنفردة تُقصي الأعلى مباشرةً؛ التعادل وحده يفتح دفاعاً منفرداً لكل متعادل (90 ثانية) ثم إعادة واحدة، ولا إقصاء إذا استمر التعادل.
- سجل تصويت، محادثة نصية للموتى، واستمرار أدوات المضيف بعد الإقصاء.
- روبوتات تكمل العدد الأدنى وتعوّض المنسحب أثناء الجولة مع الاحتفاظ بالدور وحالة الحياة.
- بيان PWA وخدمة تخزين مؤقت أولية.
- لوحة إدارة محمية على `/admindash` للمستخدمين والغرف وإعدادات الموقع وفريق الإدارة وسجل الإجراءات. لا تعرض كلمات المرور أو بصماتها.

## ما يعمل على الخادم وما ينتظر الربط

الحسابات والجلسات والغرف والأعضاء والأدوار ورسائل الجولة تعمل عبر Cloudflare Worker وD1 وDurable Objects، والصوت المباشر يعمل عبر LiveKit بتصاريح يصدرها الخادم حسب العضوية والدور والحياة. مزامنة بقية أحداث اللعب والتصويت ما زالت المرحلة التالية قبل إطلاق اللعب المتعدد الكامل.

## اتجاه التكامل

- `dist/js/state.js`: حالة اللعبة المحلية، ويمكن لاحقاً استبدال أحداثها بحالة موثوقة من الخادم.
- `dist/js/services/room-chat.js`: عميل المحادثة النصية الحيّة وإعادة الاتصال.
- `worker/index.js`: Cloudflare Worker وقناة Durable Object لكل غرفة.
- `migrations/`: مخطط D1 وتحديثاته للحسابات والجلسات والغرف والجولات والرسائل.
- `dist/js/services/livekit-voice.js`: عميل LiveKit للصوت العام وقناة أفراد الظل.
- `docs/architecture.md`: مراحل الانتقال من النموذج إلى نسخة متعددة اللاعبين.

للتجربة محلياً، قدّم مجلد `dist` عبر أي خادم ملفات ثابتة.

للنشر كـ Cloudflare Worker مع Static Assets:

```sh
npx wrangler@latest deploy
```

يلزم ضبط أسرار `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`FACEBOOK_APP_ID` و`FACEBOOK_APP_SECRET` لتفعيل الدخول الاجتماعي. لإسناد أول صلاحية مالك، أضف `ADMIN_EMAILS` في Worker Secrets بقائمة عناوين مفصولة بفواصل؛ بعد دخول المالك يمكنه إدارة بقية المشرفين من `/admindash`. الأسماء فقط موثقة في `.dev.vars.example` ولا تُحفظ الأسرار داخل المشروع.
