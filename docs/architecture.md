# مسار التطوير التقني

## 1. النموذج الحالي

واجهة ثابتة تعتمد على وحدات JavaScript أصلية، وحالة محلية في الذاكرة مع بعض التفضيلات في `localStorage`. هذا يبقي التصميم سريعاً وسهل الاختبار قبل تثبيت بروتوكول الخادم.

## 2. خادم اللعبة

يكون الخادم صاحب القرار الوحيد في: توزيع الأدوار، انتقال المراحل، المؤقتات، قبول الأصوات، حل التعادل، الإقصاء، وإعادة الاتصال. يرسل العميل نوايا فقط (`vote.cast`, `speech.request`, `night.action`) ويتلقى لقطات حالة مقيّدة حسب دور اللاعب.

## 3. الوقت الحقيقي والصوت

- WebSocket أو خدمة غرف لحالة اللعبة والرسائل المصرح بها.
- LiveKit لقنوات الصوت، مع رموز وصول يصدرها الخادم بحسب المرحلة والدور.
- قناة مافيا خاصة ليلاً، وقناة عامة نهاراً، ومنع نشر المسار الصوتي للموتى.
- إدارة طابور الكلام من الخادم حتى تتطابق المؤقتات عند جميع اللاعبين.

## 4. العودة والروبوت

يُحجز مقعد اللاعب بمعرّف جلسة قابل للاسترجاع. بعد مهلة قصيرة، ينتقل المقعد إلى وكيل محدود القواعد، ثم يعيد الخادم السيطرة للاعب عند عودة الاتصال. لا يحصل الروبوت أو العميل العائد على معلومات لم يكن الدور مخولاً برؤيتها.

## 5. PWA ثم التطبيق

النموذج يتضمن بيان تثبيت وخدمة تخزين مؤقت أولية. قبل الإنتاج يلزم: أيقونات PNG متعددة، إشعارات، سياسة تحديث للخدمة، شاشة عدم اتصال، وإدارة أذونات الميكروفون. يمكن لاحقاً تغليف تجربة الويب عبر Capacitor أو نقل طبقة العرض إلى تطبيق أصلي مع الإبقاء على بروتوكول الخادم نفسه.
